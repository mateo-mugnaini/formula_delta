# Formula Delta UX Principles

## 1. Glance First

The user frequently looks away to watch the broadcast. The interface must be
understandable in short glances without requiring navigation through multiple
views.

## 2. The Timing Tower Is Primary

Current classification, gaps, intervals, lap times, tyres, tyre age, and pit
information form the primary experience. Secondary panels must not visually
compete with the timing tower during a live session.

## 3. Persistent Information Beats Temporary Information

Formula Delta exists to keep useful race context visible after a broadcast
graphic disappears. Important current state and recent Race Control history
should remain available without intrusive notifications.

## 4. Stable Layouts Beat Motion

Ordinary live updates should not move the interface unnecessarily. Animation is
reserved for meaningful state changes and should respect reduced-motion
preferences.

## 5. Semantic Emphasis Is Selective

Green, yellow, VSC, Safety Car, red flag, pit activity, penalties, and major
Race Control events deserve stronger emphasis. Routine timing changes should
remain calm and readable.

## 6. Never Fabricate Missing Data

Unavailable or unconfirmed values must be represented honestly. The interface
should distinguish zero, empty, unavailable, and not-yet-received values where
the domain requires it.

## 7. Source Independence

The user experience should be substantially the same for live and replay
sessions. Source mode and replay controls may be visible, but timing features
must not require separate UI logic for each source.

## 8. Recovery Must Be Understandable

Connection loss, reconnection, stale data, and unavailable capabilities should
be visible without blocking the entire dashboard. A recovered authoritative
snapshot should restore trust in the displayed state.

## 9. Controls Must Match Consequences

The most common controls should be direct and easy to understand. Broadcast
delay adjustment should expose small increments and clear presets. Replay
controls should communicate playing, paused, completed, and failed states.

## 10. Density Must Remain Readable

Information density is intentional, but it must not become visual noise. Use
alignment, hierarchy, restrained separators, and consistent abbreviations to
make dense information scannable.
